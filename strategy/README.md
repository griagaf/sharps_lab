# Байесовская стратегия прогулов

Стратегия для конкурса «Мастер прогулов 80-го уровня» курса «Введение в C# и платформу .NET», НГУ ФИТ. По истории вопросов она оценивает правила преподавателей и прогуливает пару, если вероятность вопроса ниже 0,3 %. [Условия конкурса](https://sites.google.com/view/fitnsudotnet/)

`.NET 10` · `Байесовский вывод` · `Без NuGet-зависимостей`

| Показатель | Значение |
|:-----------|:---------|
| Средний счёт стратегии на 26 000 семестрах | **348,15** |
| Доля вылетов в этом прогоне | **1,10 %** |
| Верхняя граница среднего для участника | **около 373,2** |
| Абсолютный максимум за один семестр | **700** |

## Задача

Семестр длится 100 дней, в каждом дне по шесть пар. За день начисляется одно очко за пирожок, за каждый удачный прогул ещё одно. Если студента спросили на пропущенной паре, счёт за весь семестр обнуляется. Конкурс оценивает среднее за 1000 семестров.

Тип правила каждого преподавателя случайно выбирается в начале семестра. Расписание вопросов определяется правилами и бросками монеты независимо от посещаемости. Стратегия видит исходы посещённых пар. Если после прогула семестр продолжился, это тоже наблюдение: на пропущенной паре студента точно не спросили. Поэтому к началу следующего дня весь вчерашний вектор вопросов известен. Посещение и прогул дают одну и ту же информацию в тех случаях, когда студент остаётся в игре.

## Как стратегия принимает решение

Для каждого преподавателя стратегия рассматривает 22 гипотезы. В модели из лабораторной три типа правил равновероятны, а предметы внутри каждого типа выбираются равномерно.

| Правило | Гипотезы | Начальный вес каждой |
|:--------|---------:|---------------------:|
| Спросить с вероятностью 50 % | 1 | 1/3 |
| Спросить, если вчера спросили по предмету A | 6 | 1/18 |
| Спросить, если вчера спросили ровно по одному из предметов A и Б | 15 | 1/45 |

1. За каждый прошедший день стратегия сверяет гипотезы с наблюдением. Вес случайного правила умножается на 1/2. У согласующихся с наблюдением детерминированных гипотез вес сохраняется, у остальных обнуляется.
2. После нормировки весов стратегия вычисляет вероятность вопроса сегодня. Она складывает веса детерминированных гипотез, предсказывающих вопрос, и добавляет половину веса случайной гипотезы.
3. При вероятности ниже `0,003` пара прогуливается. В первый день вчерашний вектор пуст, поэтому вероятность вопроса по каждому предмету равна `1/3 × 1/2 = 1/6` и стратегия посещает все пары.

Один удачный прогул приносит очко, а вылет стоит всего итогового счёта. При типичном итоге порядка 350 очков баланс `(1 − p) × 1 ≈ p × 350` даёт ориентир для порога около 0,003. Постоянный порог подобран экспериментально.

## Почему у среднего балла есть потолок

Представим оракула, который знает все правила преподавателей и выбранные ими предметы. Будущие броски монеты ему неизвестны. Стратегия студента может использовать только историю, а оракул может воспроизвести любое такое решение. Значит, оптимальный результат оракула ограничивает сверху результат любой стратегии.

- **Детерминированные пары.** По вчерашнему вектору оракул заранее знает, где спросят. Пропустить пару без вопроса выгодно всегда: это даёт очко без риска и сохраняет всю информацию для следующего дня. На пару с вопросом оракул идёт, чтобы сохранить семестр.
- **Случайные пары.** Если оракул хочет пропустить хотя бы одну такую пару, вероятность вылета за этот день не меньше 1/2. Заменим эти прогулы посещениями. В ветке, где все прогулы удались бы, изменение стоит до шести очков. В ветке, где случился бы вылет, можно дальше ходить на все пары и сохранить как минимум 100 очков за пирожки. Ожидаемый выигрыш от замены положителен, поэтому оптимальный оракул посещает все случайные пары.

Точная формула потолка оракула — **100 плюс ожидаемое число детерминированных пар без вопроса за весь семестр**. Оценка по 400 000 симулированных семестров составляет **377,2 ± 0,2** очка.

### Граница для участника

В день 1 правила скрыты, поэтому любой набор прогулов с хотя бы одной парой создаёт риск вылета не меньше 1/6. Замена всех прогулов первого дня посещениями стоит до шести очков при удачном исходе и спасает минимум 100 очков при вылете. Даже при таких оценках ожидаемый выигрыш положителен. Продолжение исходной стратегии можно воспроизвести по той же истории вопросов в ветках, где она выжила бы.

Теперь дадим участнику правила **после первого дня**. Со второго дня он сможет играть как оракул. В первый день все детерминированные преподаватели молчат, и оракул в среднем пропускает `6 × 2/3 = 4` пары. Участник их посещает, поэтому его средний результат ограничен сверху величиной **377,2 − 4 ≈ 373,2**. Это оценка верхней границы по той же модели. Скрытые правила после первого дня могут опустить истинный оптимум ещё ниже.

У байесовской стратегии основная часть отставания от оракула приходится на первые десять дней, пока несколько правил одинаково хорошо объясняют короткую историю. Позже многие гипотезы отсеиваются, и безопасные прогулы становятся предсказуемыми. Пороговая стратегия набирает около 348 очков в среднем. Точный максимум при скрытых правилах остаётся открытым.

В отдельном семестре можно набрать и 700 очков. Если все шесть правил детерминированные, вопросов не будет весь семестр: в первый день вчерашний вектор пуст, и таким он останется.

## Сборка

Из корня репозитория, с установленным .NET 10 SDK.

```bash
dotnet build strategy/Strategy.csproj -c Release
```

Проект собирается в библиотеку. У `BayesSkipStrategy` есть публичный конструктор без параметров. Раннеру нужно вызывать `DecideDay` перед каждым днём, начиная с 1. Для каждого предмета `true` означает пойти на пару, `false` — прогулять.

Проверочный прогон в локальном симуляторе из lab1 занял 4,2 секунды на 1000 семестров в Release. Средний счёт составил 341,25 при 10 вылетах.
